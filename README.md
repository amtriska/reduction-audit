# reduction-audit

Code and data for the note *Decomposing the zero reductions of a signature-based Gröbner basis implementation: a per-signature prediction and case study* (in preparation).

## Run

```
pip install -e ".[test]"
python tools/vendor_sympy.py --check     # vendored f5b matches the pinned SymPy
pytest -m "not slow"                     # about 1 minute
pytest                                   # all tests, about 5 minutes
python -m reduction_audit.records        # regenerate runs/, about 5 minutes
python tools/make_tables.py              # tables/*.tex from runs/
```

If [Singular](https://www.singular.uni-kl.de) is on the PATH, the tests also recompute the
predicted signatures independently in Singular for each of the 69 declared instances; otherwise
those tests are skipped.

`python -m reduction_audit.records`, run from the repository root, rewrites `runs/`:
`decompositions.json` (structured systems), `determinantal/*.json`, `sweep/*.json`,
`ablations/*.json` (plain, `keep_zeros` and `syzygy_criterion` runs side by side),
`blind_spot/*.json` (generation numbers of the reductions `keep_zeros` leaves), and
`provenance.json`, which records the commit, SymPy and Python versions the files were generated
with. `tools/make_tables.py` builds every table in the note from these files.

`reduction_audit/_vendored_sympy_gb.py` is SymPy 1.14.0's `groebnertools.py` with instrumentation,
generated by `tools/vendor_sympy.py`; regenerate it rather than editing it. Its two options,
`syzygy_criterion` and `keep_zeros` (zero results kept in B, as in Sun and Wang's F5B), are off by
default; with both off it behaves exactly as upstream.
